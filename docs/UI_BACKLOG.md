# UI 통합 개선 백로그 (보류)

> 상태: **UI 개선 보류** · 작성: 2026-10-12  
> 목적: 게임 로직과 콘텐츠 개발을 우선하고, UI/UX 완성도는 별도 작업 단계에서 **한 번에 정리**한다. 이 문서는 구현 지시가 아닌 향후 작업용 기록이다.

## 확정된 화면 방향

- **모바일 세로 화면** 우선. 전투와 던전 가시 영역을 가능한 크게 유지한다.
- 상단 첫 줄: **왼쪽 미니맵 / 가운데 현재 위치·경과 시간 / 오른쪽 메뉴**.
- 그 아래: **HP·MP·XP 상태바**, 이어서 **현재 스킬과 레벨을 즉시 확인할 수 있는 간결한 스킬 아이콘 바**.
- DCSS처럼 전투 상황을 읽을 수 있는 **짧은 실시간 로그**, 필요할 때 전체 기록을 펼치는 방식.
- **장비창과 가방창**은 전투 화면을 가리지 않도록 열고 닫을 수 있는 모바일 친화적 패널로 통합한다.
- 정보 밀도는 높되 장식은 최소화한다. 목업보다 단순하고 빠르게 읽히는 UI를 지향한다.

## 통합 작업 시 주의할 기능적 경계

1. **게임 로직과 UI를 분리**한다. `src/sim/gear.ts`, `src/sim/consumables.ts`, `src/sim/itemEffects.ts` 등은 상태 변경과 규칙을 담당하고, UI는 이를 호출하고 결과를 표시한다.
2. **아이템의 내부 ID/UID와 표시 이름을 구분**한다. 감정되지 않은 아이템의 표시 이름은 `src/sim/identification.ts`의 규칙을 따른다.
3. 장비 슬롯은 `src/sim/gear.ts`의 슬롯 및 장착 제한을 기준으로 한다. 보조손(offhand)에는 방패 또는 마법서가 들어가며, 양손 주손이면 막힌다(2026-10-12 구현, [SKILL_TRAINING.md](SKILL_TRAINING.md) §2).
4. 강화/저주/장착 상태를 UI에서 임의로 계산하지 않는다. 시뮬레이션 상태를 단일 진실 공급원으로 사용한다.
5. **양손무기-방패 제한**, 저주받은 장비 해제 금지, 감정할 아이템이 없을 때의 처리 등 실패 상태도 명확하게 안내한다.
6. 게임이 멈추는 조건과 패널을 열었을 때의 입력/시간 흐름을 명시적으로 결정하고 테스트한다.

## 관련 코드

- `src/ui/hud.ts` — 상단 HUD, 미니맵 슬롯, 상태바, 메뉴
- `src/ui/skillBar.ts` — 스킬 아이콘/레벨, 상세 패널
- `src/ui/inventorySheets.ts` — 장비창·가방창·아이템 액션·현재 임시 감정 UI
- `src/ui/gameLog.ts` — 실시간 메시지 및 기록 패널
- `src/sim/gear.ts` — 장착/해제/강화/저주 및 장비 효과
- `src/sim/consumables.ts`, `src/sim/itemEffects.ts`, `src/sim/identification.ts` — 소모품 효과와 감정
- `src/data/json/items.json` — 아이템 종류/효과/임시 타일
- `docs/ITEMS.md` — 아이템 데이터 구조

## 나중에 UI 작업을 시작할 때의 완료 기준

- 주요 화면이 **모바일 세로 한 손 조작**에 맞고 HUD와 겹치지 않는다.
- 모든 장비/아이템 행동이 **게임 내 패널에서** 처리되며 브라우저 `prompt`에 의존하지 않는다.
- 아이템/장비/스킬/상태이상은 텍스트를 읽기 전에 **아이콘·수치·상태 표시만으로 구분**된다.
- 실패·취소·저주·장비 제한·감정 여부 등의 예외 상황에서 일관된 피드백을 준다.
- 기존 시뮬레이션 동작과 자동 테스트가 유지되고, 실제 모바일 세로 화면에서 수동 확인을 마친다.

**현재 결정:** 이 문서만 남기고 UI 리디자인·아이콘 교체·감정 모달 작업은 지금 진행하지 않는다.
