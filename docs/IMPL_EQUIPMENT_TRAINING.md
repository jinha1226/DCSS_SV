## 0. 이번 범위가 아닌 것 (만들지 마라)

아래는 아직 사용자가 정하지 않은 것들이다. 임시로 둔 것은 임시인 채로 두고, 새로 설계하지 않는다.
- **새 마법 설계.** 마법 목록은 나중에 "우리 스타일"로 다시 만든다. 이번에는 §3의 임시 배정만 한다.
- **스킬 마일스톤 효과(2/4/6/8단계, `axe.wide` 등)를 바꾸는 것.** id 이름 변경만 한다.
- **새 계열의 무기 아이템.** 둔기, 창, 맨손 무기 아이템은 이번에 만들지 않는다. 계열 타입과 스킬, 적성 키만 받게 한다.
- **마법 무기의 랜다트.** 지팡이, 마법봉, 마법서는 이번에는 일반 품질만 만든다.
- **직업 이름 변경.** 컨저러는 id와 이름을 그대로 둔다. 파괴술이 없어진 뒤의 이름은 사용자가 정한다.
- 밸런스 수치를 다듬는 것. 이 문서에 나온 수치는 전부 자리 표시용이다. 데이터 파일에 두고, 코드에 박지 않는다.

## 1. 스킬 데이터 (`skills.json`, `src/data/skills.ts`)

최종 스킬 id는 20개다(기본 7 + 무기 6 + 학파 7).

| 구분 | id |
|---|---|
| 기본 7 | `fighting` `armour` `dodging` `shield` `stealth` `spellcasting` `throwing` |
| 무기 6 | `blade` `axe` `mace` `polearm` `unarmed` `ranged` |
| 학파 7 | `fire` `ice` `air` `earth` `summoning` `hexes` `necromancy` |

**id를 바꾼다**
- `long_blade`는 `blade`로 바꾼다. 효과 키도 `long_blade.*`에서 `blade.*`로 바꾼다.
- `bow`는 `ranged`로 바꾼다. 효과 키도 `bow.*`에서 `ranged.*`로 바꾼다.
- `translocation`은 `hexes`로 바꾼다.
- 저장된 데이터(세이브)는 아직 없으니 이전 id를 호환하는 코드는 만들지 않는다.

**지운다**
- `conjuration`. `skills.ts`의 `SCHOOLS`에서 `conjuration`, `alchemy`, `forgecraft`, `translocation`도 뺀다.

**더한다**
- `mace`, `polearm`, `unarmed`: `axe`처럼 `*.damage` perLevel 효과 하나만 둔다. 값은 도끼와 같게 한다.
- `stealth`: 효과는 아직 비워 둔다. 수면 판정에 연결하는 것은 이번 범위가 아니다. 레벨만 오르면 된다.
- `ice`, `air`, `earth`, `summoning`, `necromancy`: 효과 없이 둔다. 위력은 기존 `spellExcess`가 맡는다.

**`WeaponFamily` 타입과 `items.ts`의 검증**
- `axe | bow | long_blade`를 `blade | axe | mace | polearm | unarmed | ranged`로 바꾼다.
- `AXES`, `BOWS` 같은 헬퍼는 새 이름에 맞춰 정리한다.

## 2. 적성 (`species.json`)

키를 20개 스킬 id로 바꾼다. 아래 규칙을 **기계적으로** 적용한다. 새로 판단하지 않는다.
- `long_blade`는 `blade`로, `bow`는 `ranged`로 키 이름만 바꾸고 값은 그대로 둔다.
- `mace`, `polearm`: `axe` 값을 복사한다.
- `unarmed`: `fighting` 값을 복사한다.
- 7개 학파와 `spellcasting`: 기존 `magic` 값을 복사한다.
- `stealth`: `dodging` 값을 복사한다.
- `throwing`, `shield`, `armour`, `dodging`, `fighting`: 지금 값을 유지한다.
- `skillData(id).aptitude`가 가리키는 키도 맞춘다.

종족 27개의 적성표를 다시 짜는 일은 밸런스 단계에서 한다.

## 3. 마법 데이터 (`spells.json`)

- `schools`는 `school: string` 하나로 바꾼다. 로더는 학파가 정확히 하나인지 검사한다.
- **임시 배정**이다. 마법을 다시 설계할 때 통째로 교체한다.

| 마법 | 원래 | 임시 학파 |
|---|---|---|
| 마력침, 집광선 | conjuration | air |
| 파동탄 | conjuration | fire |
| 분광창 | conjuration | ice |
| 중력꽃, 붕괴장 | conjuration | earth |
| 공허폭발 | conjuration | necromancy |
| 불씨, 작열선, 잿불구름 | fire | fire |
| 점멸, 위상막 | translocation | hexes |

- **필요 학파 레벨**은 `requiredLevel(spell) = spell.requirement ?? max(0, STEP × (level - 1))`로 정한다.
  - `STEP`은 데이터에 둔다(`dungeon.json` 등). 처음 값은 3이다.
  - 그래서 1레벨 마법은 학파 0에서 바로 쓸 수 있다.
- 실패율 코드가 남아 있으면 지운다. 마법을 막는 것은 MP와 쿨다운뿐이다.

## 4. 장비 자리와 마법 무기

### 4-1. 아이템 종류 (`items.json`, `items.ts`)

마법 무기 세 종류를 추가한다. 모두 `school`과 `tier`(0, 1, 2)를 가진다.

| kind | 손 | 자리 | 하는 일 |
|---|---|---|---|
| `staff` (지팡이) | 양손 | 주손 | 자동 공격이 학파 마법이다. 마법 버튼을 준다. 위력 보너스가 있다(`power` 데이터 값) |
| `rod` (마법봉) | 한손 | 주손 | 자동 공격이 학파 마법이다. 위력 배율은 낮다(`power` < 1). **버튼은 주지 않는다** |
| `spellbook` (마법서) | — | 보조손 | 마법 버튼만 준다. 자동 공격은 없다 |

- 이미 소모품 `wand`(완드, `wand_sparks`)가 있으니, 마법봉의 kind는 `rod`로 한다. 화면 이름은 "마법봉"이다.
- **티어는 주는 마법을 정한다.** 장비는 자기 학파에서 `level ≤ TIER_MAX_LEVEL[tier]`인 마법을 모두 준다. 처음 값은 `[3, 6, 9]`이고 데이터에 둔다. 잠긴 마법(필요 학파 레벨 미달)도 목록에는 들어간다.
- 데이터 항목은 학파 × kind × 티어 조합으로 만든다. 이름은 "입문/숙련/대가 ○○ 지팡이"처럼 붙인다. `depthWeights`는 티어에 맞춰 `[8,2,0]`, `[2,6,2]`, `[0,2,8]`처럼 둔다.
  - 그 학파에 해당 티어로 줄 마법이 하나도 없으면 그 조합은 만들지 않는다.
  - 자동 공격용 피해 마법이 없는 학파는 지팡이와 마법봉을 만들지 않는다. `hexes`가 그렇다. 마법서만 만든다.
- 타일은 지금 있는 것 중 아무것이나 임시로 쓴다. 사용자가 나중에 일괄 교체한다.

### 4-2. 보조손 (`types.ts`, `equipment.ts`)

- `gear.shield` 칸을 **`gear.offhand`**로 넓힌다. 방패나 마법서가 들어간다.
  - 방패 판정(`w.gear.shield`를 쓰는 곳 전부)은 "보조손 아이템이 방패인가"로 바꾼다.
- 주손이 양손 무기(`hands === 2`, 지팡이 포함)이면 보조손 장착을 막는다.
  - 이미 보조손에 무언가 있는 상태에서 양손 무기를 들면, 보조손 아이템은 가방으로 돌아간다.
- 주손은 지금의 `w.weapon`이다. `WeaponItem`에 마법 무기(지팡이, 마법봉)를 담을 수 있게 할지, 마법 무기용 타입을 따로 만들지는 구현하는 쪽이 정한다. 단, **자동 공격 경로가 하나로 모이게** 한다. 지금 `combat.ts:285`는 `attackMode === 'magic'`일 때 따로 분기한다.

### 4-3. `attackMode`를 없앤다

- 자동 공격의 종류는 직업(`heroDef.attackMode`)이 아니라 **주손 장비**로 정한다. 주손이 지팡이나 마법봉이면 마법 자동 공격을 한다.
- 이 필드를 쓰는 곳은 다음과 같다. 전부 장비 기준으로 바꾸고, `jobs.json`의 `attackMode`는 지운다.
  - `skills.ts:75,86`
  - `equipment.ts:195`
  - `combat.ts:285`
  - `spells.ts:46,61,438`
  - 몬스터 AI의 `attackMode`는 다른 것이니 건드리지 않는다.

### 4-4. 마법 목록 (`spells.ts`)

- `knownSpells(w)`: 장착한 지팡이나 마법서가 주는 마법 가운데, 필요 학파 레벨을 넘은 것만 고른다.
- `lockedSpells(w)`: 장착 장비가 주지만 아직 잠긴 마법을 고른다. UI 표시용이다.
- `basicSpell(w)`: 주손이 지팡이나 마법봉일 때, 그 학파에서 쓸 수 있는 피해 마법을 고른다. 고르는 규칙은 지금 규칙(낮은 쪽에서 두 번째)을 유지한다. 마법봉은 피해에 `power` 배율을 곱한다.
- `paidSpells(w)`: 버튼으로 쓰는 마법이다. 장비가 주는 것만 고른다. 마법봉은 버튼을 주지 않는다.
- `openSkills`로 마법을 막는 코드는 지운다.

### 4-5. 배움 아이템 정리

- 줍기만 하면 학파가 열리던 바닥 아이템 `book`과 무기 계열이 열리던 `path`(`placeNewPath`)는 새 구조에서 의미가 없으니 지운다.
- 마법서는 이제 다른 장비처럼 바닥 드롭과 레벨업 카드로 나온다.
- `equipment.ts:195`의 "마법 직업이면 화염 책을 놓는다"는 지운다.
- `openSkills`는 "UI에 보여 줄 스킬"로만 남긴다. XP가 한 번이라도 들어간 스킬은 자동으로 추가한다. 이걸로 무엇을 막는 데 쓰지 않는다.

## 5. 훈련 (`skills.ts`)

`activeTraining`과 `trainSkills`를 아래 규칙으로 바꾼다. 킬로 들어오는 `gainExperience(w, amount)` 경로는 그대로 둔다.

```
기본 = fighting, armour, dodging, stealth, spellcasting, throwing
      + shield (보조손이 방패이고 주손이 한손일 때)
기본 스킬은 각각 amount × 적성을 받는다.

주손 계열 = 무기면 family, 지팡이나 마법봉이면 school
보조손 학파 = 보조손이 마법서면 그 school, 아니면 없음

보조손 학파가 없으면: 주손 계열이 amount를 받는다.
보조손 학파가 있으면: 주손 계열 amount/2, 보조손 학파 amount/2.
  두 계열이 같으면(예: 화염 마법봉 + 화염 마법서) 합쳐서 amount를 받는다.
받은 몫에 각자 적성을 곱한다.
```

- 지금 무기 계열을 훈련할 때 "마법 직업이면 제외"하는 조건은 지운다. 장비가 정한다.
- 투척은 투척물이 있든 없든 항상 오른다.
- 교차 훈련은 없다.
- 기존 레벨업 처리(전투가 오르면 최대 HP, 주문시전이 오르면 MP)는 그대로 둔다.

## 6. 레벨업 아이템과 위치 티어

### 6-1. 위치 티어

- `lootTier(w): 0 | 1 | 2`를 하나 만든다. 현재 던전 노드(`dungeonGraph`)의 `difficulty`를 쓴다.
  - 처음 경계는 `difficulty` 1–4 → 0, 5–10 → 1, 11 이상 → 2이고, 데이터에 둔다.
- `equipment.ts`에서 `w.depth - 1`로 티어를 구하는 곳(`depthWeights` 인덱스, `RANDART`/`BRAND` 인덱스, 대략 33, 54, 158, 177번 줄)을 전부 `lootTier(w)`로 바꾼다. 바닥 드롭과 레벨업 카드가 같은 함수를 쓰게 하는 것이 목적이다.

### 6-2. 카드 세 장 (`rewards.ts`)

1. **무기 카드**: 주손 계열로 만든다.
   - 무기면 지금처럼 `generateWeapon(w, family)`를 쓴다. 일반이나 랜다트가 위치 티어를 따라 나온다.
   - 지팡이나 마법봉이면 같은 학파, 같은 kind의 아이템을 `lootTier` 가중치로 고른다. 랜다트는 없다.
2. **장비 카드**: 지금의 방어구와 장신구 후보에 보조손 아이템(방패, 마법서)을 더한다.
   - 주손이 양손이면 보조손 아이템은 뺀다.
   - 마법서 학파는 아무 학파나 되고, 티어는 `lootTier`를 따른다.
3. **소모품 카드**: 그대로 둔다.

### 6-3. 건너뛰기

- `skipReward(w, 'heal' | 'gold'): boolean`를 추가한다. 하는 일은 `chooseReward`와 같다. 카드를 지우고, 대기 중인 선택 수를 하나 줄이고, 다음 카드를 낸다.
  - `heal`: 최대 HP와 MP의 일정 비율을 채운다. 처음 값은 30%다.
  - `gold`: `기본 + 계수 × difficulty`만큼 금화를 준다. 처음 값은 10 + 5×difficulty다.
  - 수치는 데이터에 둔다.
- 한 번 고른 카드 세트에서 두 번 받을 수 없게 한다. `chooseReward`와 같은 방식이다.

## 7. UI

- **레벨업 카드 화면**: 카드 세 장 아래에 "건너뛰기: 회복 / 금화" 버튼 둘을 둔다. 엄지로 누를 수 있게 최소 48px로 한다.
- **가방**(`inventorySheets.ts`)
  - 보조손 칸을 표시하고 장착과 해제를 할 수 있게 한다.
  - 양손 무기를 들고 있으면 보조손 칸을 막고 이유를 한 줄로 보여 준다.
- **마법 버튼**(`skillBar.ts`): 잠긴 마법은 흐리게 보이고 "○○ 학파 N 필요"를 표시한다. 누르면 아무것도 하지 않는다.
- **상태 화면**: 20개 스킬을 기본, 무기, 학파 세 묶음으로 나눠 보여 준다. 레벨이 0이고 XP도 없는 스킬은 숨긴다.

## 8. 테스트 (`tests/unit`)

기존 테스트는 id 이름을 바꾼 것만 고친다. 규칙이 바뀌어 기대값이 달라진 테스트는, 왜 바뀌었는지 테스트 이름이나 주석에 적는다. 새로 넣을 테스트는 다음과 같다.

1. 무기만 들면 주손 계열이 전액을 받는다. 기본 7개도 각각 전액을 받는다.
2. 검 + 화염 마법서면 `blade`와 `fire`가 반씩 받는다. 화염 마법봉 + 화염 마법서면 `fire`가 전액을 받는다.
3. 방패 + 한손 무기면 `shield`가 오르고, 양손이면 오르지 않는다.
4. 투척물이 0개여도 `throwing`이 오른다.
5. 양손 무기를 장착하면 보조손이 가방으로 돌아가고, 다시 장착할 수 없다.
6. 마법서를 바꾸면 `knownSpells`가 바뀐다. 마법봉은 `paidSpells`가 비어 있다.
7. 필요 학파 레벨이 안 되면 잠긴다. 1레벨 마법은 학파 0에서 쓸 수 있다.
8. 컨저러는 지팡이로 자동 마법 공격을 하고, 마검사는 장검으로 자동 공격을 하면서 버튼으로 점멸을 쓸 수 있다.
9. `lootTier`가 노드 `difficulty` 경계를 따른다. 바닥 드롭과 레벨업 카드가 같은 티어를 쓴다.
10. 양손 주손이면 장비 카드에 보조손 아이템이 나오지 않는다.
11. 건너뛰기 보상은 한 번만 받는다. 회복은 최대치를 넘지 않는다. 금화는 difficulty에 비례한다.
12. 같은 시드와 같은 선택이면 카드, 스킬, 보상이 같다.
13. 데이터 검사: 모든 마법이 학파를 하나만 가진다. 모든 마법 무기의 학파가 존재한다. 종족마다 적성 키 20개가 다 있다.

`tests/bench/bots.ts`의 `bowFirst` 같은 이전 스킬 카드 헬퍼는 id만 맞춘다.

## 9. 끝내는 방법

1. 브랜치에서 작업하고 PR 하나로 main에 합친다. 커밋을 여러 개로 연달아 push하지 않는다.
2. `npm ci`, `npm run check`, `npx vite build`를 통과시킨다.
3. 문서를 고친다.
   - `docs/SKILL_TRAINING.md` 끝에 진행 기록을 단다.
   - `docs/ITEMS.md`에 지팡이, 마법봉, 마법서, 보조손을 적는다.
   - `docs/SPELLS.md`에 단일 학파, 필요 레벨 공식, 임시 배정이라는 사실을 적는다.
4. 사용자에게는 폰에서 확인할 것을 짧게 알린다.
   - 컨저러가 지팡이로 싸우는지
   - 마검사가 칼과 마법서로 싸우는지
   - 레벨업 카드 건너뛰기가 되는지
   - 잠긴 마법이 표시되는지
   - 실제 폰에서 확인하지 못했다면 확인 못 했다고 말한다.
