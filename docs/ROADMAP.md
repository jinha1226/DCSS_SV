## 1. 큰 그림

### 1.1 한 줄 정의

**DCSS를 실시간 자동전투 로그라이트로.** 휴대폰과 브라우저에서 바로 하는 15~25분짜리 판 안에 DCSS의 종족·직업·마법·브랜치·룬의 깊이를 담는다.

### 1.2 타겟

| 구분 | 누구 | 이 게임에서 얻는 것 | 역할 |
| --- | --- | --- | --- |
| 주 타겟 | DCSS가 궁금했지만 진입장벽(턴제·키보드·아스키 화면·긴 판) 때문에 못 해 본 사람, 뱀서류·로그라이트를 즐기는 모바일·웹 유저 | 익숙한 조작과 짧은 판 안에서 DCSS식 조합의 깊이 | 판매 대상 |
| 보조 타겟 | 기존 DCSS 플레이어(레딧 r/dcss, 디시 로그라이크 갤러리) | 원작 조합을 실시간으로 해 보는 재미 | 초기 테스터, 입소문 통로 |

설계가 둘 사이에서 부딪히면 **주 타겟을 우선한다.** 원작 팬에게는 "규칙과 데이터를 원작에서 가져왔다"는 신뢰를 준다(출처 표기, 코드 공개).

### 1.3 원칙 (이미 정한 것)

1. **라이선스**: 코드 GPL-3.0-or-later. DCSS 코드·규칙·수치·설명문은 출처를 남기고 자유롭게 가져온다. 그림은 CC0만 쓴다. DCSS 타일 중 재사용 불가 목록은 GPL이어도 쓰지 않는다. 직접 만든 그림(haven 등)은 GPL과 별도 저작물이다.
2. **이름**: 게임 이름에 "Dungeon Crawl Stone Soup"·"DCSS"를 넣지 않는다. "DCSS에서 영감을 받은"으로 소개한다. 저장소 이름 `DCSS_SV`는 개발용이다.
3. **좌표**: 자유 좌표와 실시간을 유지한다. 시야·지형은 칸 단위이고, 규칙이 애매한 곳(주문 범위, 밀치기)만 칸 기준으로 판정한다.
4. **마법**: 실패율 없음. 많이 쓰이는 주요 주문 위주로 학파당 6~9개.
5. **전투**: 근접은 준비 동작 없이 즉시 맞고, 근접 사거리 안에서는 이동이 느려진다(교전). 원거리·주문은 준비 동작으로 예고한다.
6. **내용 선택**: 실제 플레이 통계(CAO)와 커뮤니티 공략(디시, 위키)에서 많이 하는 것부터 넣는다.
7. **작업 방식**: Claude가 구현계획서를 쓰고, Codex(`gpt-6-luna`)가 구현하고, Claude가 검토·검증·커밋·푸시한다. 검증은 테스트·타입·빌드·봇 측정으로 하고, 스크린샷 확인은 사용자가 요청할 때만 한다.

### 1.4 배포·사업 단계

| 단계 | 어디 | 가격 | 목표 |
| --- | --- | --- | --- |
| A. 웹 알파 | itch.io(웹) + GitHub Pages | 무료(선택 후원) | 한 판이 재미있는지, 처음 온 사람이 이해하는지 |
| B. 커뮤니티 공개 | r/dcss, r/roguelikes, r/WebGames, 디시 로그라이크 갤러리 | 무료 | 피드백, 첫 팬층, 이탈 지점 파악 |
| C. 스팀 페이지 | Steam(출시 예정) | — | 위시리스트 모으기 |
| D. 스팀 얼리 액세스 | Steam | 저가(예: 4,500~7,500원, 콘텐츠 양 보고 결정) | 수익, 지속 업데이트 |
| E. 정식 출시 | Steam (+웹 무료판 유지) | 소폭 인상 가능 | — |

- 웹 무료판은 계속 유지한다. 스팀판은 편의 기능(클라우드 저장, 업적), 추가 콘텐츠, 오프라인 실행으로 차별화한다.
- GPL 의무: 스팀판에도 같은 버전의 소스 링크(GitHub 태그)와 LICENSE를 넣는다.

## 3. DCSS 데이터를 유저 친화적으로 옮기는 규칙

원작에서 가져올 때는 **수치와 관계(누가 누구보다 강한가)는 지키고, 손이 가는 관리는 덜어 낸다.**

### 3.1 시간: 턴 → 초

- 이미 있는 `dcssTime` 규칙을 모든 곳에 쓴다.
  - 몬스터 이동 4.4칸/초, 공격 1회 1.3초, 주인공 공격 0.46초(속도 10, 비용 10 기준)
  - 그 밖의 행동 비용과 속도는 비율로 옮긴다.
- 지속 시간("n턴")은 같은 비율로 초로 바꾼다. 너무 짧거나 길면 하한과 상한을 둔다.
- 휴식·탐색처럼 턴을 흘려보내는 행동은 없앤다. 회복은 실시간으로만 한다.

### 3.2 종족·직업

- 적성: DCSS 숫자 +2 이상 good, -1~+1 normal, -2 이하 bad(기존 종족으로 확인함).
- 시작 기술: DCSS 직업 값의 약 1/3.
- HP·MP·속도·시야는 기존 종족을 기준으로 비율을 맞춘다.
- 종족 특성(돌연변이)은 실시간에서 체감되는 것만 넣는다. 예: 트롤 재생, 가고일 AC, 미노 뿔, 바라치 도약. 수치만 바뀌는 자잘한 것은 묶거나 뺀다.
- 캐릭터 선택에 **추천 배지**(입문: 미노광, 첫 마법사: 딥엘 화법)와 난이도 표시를 둔다.

### 3.3 기술과 성장

- **입문자를 위해 기술을 일부 묶는다.** 장검과 단검은 칼(blade) 기술 하나다. 계열 고유의 차이(단검의 기습 보너스 등)는 기술이 아니라 **무기의 성질**로 넣는다. 원작의 기술 31개를 그대로 늘리지 않는다.


- 기술 선택 화면 없이 **자동 훈련**한다. 방어·공통 기술은 자동이고 갑옷 무게로 갑옷·회피 비중이 갈린다. 공격 기술은 최근 실제로 피해를 준 무기·학파 비율로 오른다(자동 공격 포함). 자세한 내용은 `plans/2026-10-13-skill-training-by-use.md`. 원작의 "어떤 기술을 몇 % 찍을지" 관리는 자동 훈련이 대신한다.
- 커뮤니티 정석 비중(주력 무기 우선, 보조 전투 기술은 절반)을 자동 훈련 기본값의 근거로 쓴다.
- 레벨업 보상은 획득 카드(9·18·27)를 쓴다. 부위 강화는 꺼 두고 플레이 테스트 후 결정한다.

### 3.4 마법

- 실패율 없음. 갑옷·방패 불이익은 "주문 위력 감소"나 "재사용 시간 증가"처럼 눈에 보이는 형태로만 둔다. 시전 실패는 없다.
- 주문 레벨 → MP 비용과 재사용 시간. 위력은 DCSS 공식(학파 기술 평균과 주문 시전 기술)을 단순화해 쓴다.
- 복수 학파 주문은 **주 학파 하나**에 넣고, 위력 계산에만 두 학파 평균을 쓴다. 표시는 단순하게 한다.
- 주문 배우기: 지팡이(자동 시전)와 주문책(버튼 시전)으로 얻는다. 기억 칸 관리는 없다.
- **자동 공격 칸(1차 b)**: 모바일에서 버튼을 누르지 않아도 되게 마법사의 기본 공격은 계속 자동으로 나간다. 다만 지팡이에 묶지 않고 "자동 공격 칸"에 넣은 주문이 나간다. 직업마다 기본값이 있다(원소탄술사 Magic Dart, 화염술사 Foxfire 등). 배운 공격 주문으로 바꿔 넣을 수 있고, 지팡이는 학파 위력 보너스를 주는 장비가 된다.
- 학파당 6~9개를 고른다. 기준은 플레이 통계(모그 130개)와 공략이고, 목록은 5.3에 있다.

### 3.4-1 원거리 (결정)

- 활과 투석구는 **가장 가까운 적 자동 조준**을 유지한다. 투척은 지금처럼 조준할 수 있다.
- **화살 소모 없음.** 원작도 발사기 탄약을 쓰지 않는다.
- 관통, 탄 종류(독화살 등)는 넣지 않는다. 원작에도 없다. 원거리 무기의 차이는 무기 수치와 브랜드(속성)로만 낸다.

### 3.5 아이템

- 감정: 처음 쓰면 알게 되는 지금 방식을 유지한다. 저주 등 함정 요소는 넣지 않는다.
- 갑옷과 무기 수치는 DCSS 표를 비율로 옮긴다(이미 비늘 갑옷에서 하는 방식).
- 완드와 발동 아이템은 버튼 하나로 쓰는 "충전식 스킬"로 단순화한다.
- **발동(Evocations) 기술은 없앤다(결정).** 완드의 세기와 충전 수는 완드 자체가 정한다. 깊은 층에서 나온 것일수록 강하다. 성장은 더 좋은 완드를 줍는 것이다. 필요하면 캐릭터 레벨에 조금 비례하게 한다.
- 아이템 설명은 DCSS 설명문(한국어판 우선)을 가져온다(`lore.json`).

### 3.6 몬스터

- DCSS의 HP, AC, EV, 속도, 공격, 저항, 주문은 비율로 옮긴다. 이름과 설명은 DCSS 한국어판을 쓴다.
- 특수 능력은 실시간에서 읽히는 것만 넣는다. 예: 돌진, 투척, 독, 조이기, 원거리 주문, 소환.
- 브랜치마다 원작의 대표 몬스터를 넣는다. 각 브랜치가 "다른 게임처럼" 느껴져야 한다.
- 유니크(이름 있는 적)는 층 보스처럼 등장시킨다.

### 3.7 신앙

- 원작의 신 가운데 인기와 실시간 적합도가 높은 것부터 넣는다.
- 신앙 수치(piety)는 처치나 행동으로 오르고, **권능은 버튼 1~3개**로 단순화한다.
- 신앙 조건(금기)은 하나씩만 둔다. 예: 트로그는 주문 금지, 오카와루는 단독 싸움.
- 사원 브랜치에서 신을 고른다. 처음엔 신 4개로 시작한다(5.4).

### 3.8 화면과 설명

- 숫자는 숨기지 않는다. 피해, 저항, 속도를 상태창에 그대로 보여 준다.
- 처음 보는 몬스터, 아이템, 주문에는 짧은 설명 풍선을 띄운다.
- 모든 문구는 다국어 키로 관리한다(4.3).

## 4. 아직 없는 시스템 (전부)

각 항목은 별도 구현계획서로 진행한다. 크기는 S(하루 이하) / M(며칠) / L(1주 이상)이다.

### 4.1 저장과 이어하기 (M) — 웹 알파 필수

- **판 중간 저장**: 층에 들어갈 때 자동 저장한다(DCSS처럼 1판 1저장, 불러오면 저장 삭제). `World`를 직렬화한다. RNG 상태, 층 상태, 아이템 감정, 몬스터를 포함한다.
- 저장 위치: 웹은 IndexedDB(용량 여유), 스팀판은 파일과 Steam Cloud.
- **기록**: 판 결과(종족, 직업, 깊이, 시간, 사망 원인, 승리)를 남긴다. 최고 기록과 통계 화면을 둔다.
- 버전 호환: 저장 형식에 버전을 붙이고, 맞지 않으면 "새 판 시작"으로 안내한다.
- 테스트: 저장 → 불러오기 → 같은 시드와 같은 입력이면 같은 결과가 나와야 한다(결정론).

### 4.2 설정 화면 (S)

- 소리 크기, 화면 모드(2D/3D, 가로/세로), 그래픽 품질, 슈퍼핫 켜기/끄기, 조작(스틱 크기, 왼손 모드), 언어, 진동
- 지금 URL 스위치(`?r=2d`, `?sprite=haven` 등)를 설정으로 옮긴다. URL은 개발용으로 남긴다.

### 4.3 다국어 (M) — 레딧 공개 전 필수

- 영어는 B 단계(레딧) 전에 반드시 있어야 한다.
- 모든 UI 문구를 키(`ui.hud.engaged` 등)로 바꾸고 `ko.json`, `en.json`에 둔다.
- 데이터 이름과 설명(종족, 직업, 주문, 몬스터, 아이템)은 영어 원문이 DCSS에 있으니 그대로 쓴다. 한국어는 DCSS 한국어판을 먼저 쓰고, 빠진 것만 번역한다.
- 글꼴: 한글 글꼴을 웹에 포함하거나 지정해서 한글이 □로 깨지는 문제를 함께 해결한다.
- 테스트: 모든 키가 두 언어에 있는지, 없는 키를 쓰지 않는지 검사한다.

### 4.4 신앙 (L)

  - **트로그**: 광폭화(버튼), 회복 가속. 금기: 주문 사용

  - **마흘렙**: 처치 시 HP 회복, 파괴 주문 권능. 금기 없음

### 4.10-1 맵 볼트 대량 도입 (L) — M1~M2, 많이 넣을수록 좋다

층 수는 늘리지 않는다. 무작위로 만든 층 안에 원작 개발자들이 손으로 만든 방과 구조물(맵 볼트)을 끼워 넣어, 같은 층이라도 매번 다른 사건이 생기게 한다. 원작 느낌을 가장 싸게 올리는 작업이고, GPL이라 원작 지도를 그대로 가져올 수 있다.

- **원본**: DCSS `crawl-ref/source/dat/des/` 아래 `.des` 파일. 수천 개의 볼트가 있다(미니볼트, 장식, 브랜치 끝 방, 특수 방). 구현 전에 sparse checkout으로 `/mnt/d/PROJ_SV/reference/dcss-source/dat/des`에 받아 둔다.
- **변환기** `tools/importVaults.mjs`
  - `.des`의 `NAME`, `TAGS`, `DEPTH`, `ORIENT`, `MAP … ENDMAP`, `KFEAT`/`KMONS`/`KITEM`, `SUBST`/`NSUBST`를 읽는다.
  - 우리 지도 형식(벽, 바닥, 문, 물, 계단, 몬스터·아이템 자리)으로 바꿔 `src/data/json/vaults.json`에 넣는다.
  - **Lua가 들어간 볼트는 건너뛴다.** 처음엔 순수 지도(미니볼트, 장식, 작은 방)만 가져온다.
  - 크기 제한을 둔다. 예: 20×20 이하만 쓰고, 큰 것과 브랜치 끝 방은 별도로 고른다.
  - 우리 게임에 없는 지형(용암, 나무, 투명 벽, 제단 신)과 몬스터·아이템은 대응표로 바꾼다. 대응이 없으면 그 볼트를 건너뛰고 건너뛴 이유를 목록으로 남긴다.
  - 출처 표기: 볼트마다 원본 파일명과 이름을 남긴다(GPL 고지).
- **배치**: 층 생성기가 깊이와 브랜치 태그에 맞는 볼트를 층마다 1~4개 고른다. 빈 공간에 넣고 통로로 잇는다. 같은 판에서는 반복하지 않는다.
- **실시간 조정**: 원작의 문 열기, 비밀 문, 레버는 우리 게임에 맞게 단순화하거나 뺀다. 함정은 넣지 않는다.
- **볼트 미리보기**: `branches.html` 옆에 볼트 둘러보기 페이지를 만든다. 원작 이름, 깊이 태그, 우리 변환 결과를 함께 보여 준다.
- **목표 수량**: 1차 100개 이상(초반 층 중심), 이후 수백 개로 늘린다. 변환기가 있으면 수량을 늘리는 비용은 작다.

### 4.10-2 포털 던전 (M) — 선택 경로

- 필수 경로가 아니다. 층에 가끔 입구가 나타나고, 들어가면 1층짜리 짧은 보너스 지역이다. 일정 시간이 지나면 입구가 닫힌다(원작 방식). 판 길이를 늘리지 않는다.
- 1차 후보: 하수도(초반), 얼음 동굴(중반). 이후 납골당, 화산, 미궁, 지구랏.
- 지도는 원작 `.des`의 포털 볼트를 변환기로 가져온다. 보상은 장비와 금화다.

### 4.11 성능과 기기 (M)

- 저사양 휴대폰 60fps 목표. 3D 품질 단계, 타일 시트 크기 관리, 몬스터 수 상한
- 첫 로딩 5초 이내(3G 기준 아님, 일반 LTE 기준)

### 4.12 피드백과 오류 보고 (S)

- 게임 메뉴에 "의견 보내기" 링크(itch.io 댓글, Discord, GitHub 이슈)
- 오류가 나면 화면에 알리고 복사 가능한 보고 텍스트(버전, 시드, 오류)를 보여 준다. 개인정보는 수집하지 않는다.
- 선택형 익명 통계(판 결과만)는 C 단계 이후에 검토한다. 넣는다면 반드시 동의를 받는다.

### 4.13 스팀판 (L) — D 단계

- 데스크톱 포장: Tauri(가벼움) 또는 Electron. 웹 빌드를 그대로 쓴다.
- Steamworks: 업적, Steam Cloud 저장, 오버레이. 컨트롤러 지원(이동 스틱과 버튼)
- 스토어 자료: 캡슐 이미지, 스크린샷, 트레일러(30~60초). 키 아트는 직접 만든 그림으로 한다(haven 스타일 확장).
- 가격은 콘텐츠 양과 플레이 시간을 보고 정한다.
- GPL 고지와 소스 링크를 넣는다.
